    <h2 class="text-2xl font-semibold text-neutral-900 dark:text-neutral-100">What it does</h2>
    <p class="text-neutral-600 dark:text-neutral-400 leading-relaxed">
      The <code class="text-purple-600 dark:text-purple-300 bg-purple-50 dark:bg-purple-900/50 px-1.5 py-0.5 rounded">scroll-padding</code> shorthand (and longhands like{" "}
      <code class="text-purple-600 dark:text-purple-300 bg-purple-50 dark:bg-purple-900/50 px-1.5 py-0.5 rounded">scroll-padding-top</code>) applies to the <strong>scroll container</strong>: the element whose overflow creates the scrollport. It defines an inner inset from each edge of that scrollport when the browser computes scroll snap alignment and scroll positioning APIs.
    </p>
    <p class="text-neutral-600 dark:text-neutral-400 leading-relaxed">
      A common document-level pattern is <code class="text-purple-600 dark:text-purple-300 bg-purple-50 dark:bg-purple-900/50 px-1.5 py-0.5 rounded">html {"{"} scroll-padding-top: 4rem; {"}"}</code> (or the same on <code class="text-purple-600 dark:text-purple-300 bg-purple-50 dark:bg-purple-900/50 px-1.5 py-0.5 rounded">:root</code>) so hash navigation and focus scrolling leave room for a sticky site header instead of tucking headings underneath it.
    </p>

    <h2 class="text-2xl font-semibold text-neutral-900 dark:text-neutral-100">Scroll snap and <code class="text-purple-600 dark:text-purple-300">scrollIntoView</code></h2>
    <p class="text-neutral-600 dark:text-neutral-400 leading-relaxed">
      For scroll snapping, padding on the scrollport changes where snap points settle relative to the visible area. For programmatic scrolling and element-focused scrolling, the same inset is used so the &quot;optimal&quot; visible region respects your reserved chrome. For horizontally scrollable flex and grid strips where overflow alignment matters, the <a href="/l/safe-alignment" class="inline whitespace-nowrap text-purple-600 dark:text-purple-300 underline font-mono text-sm px-1.5 py-0.5 rounded bg-purple-50 dark:bg-purple-900/50">CSS safe alignment</a> lab is a good companion.
    </p>

    <h2 class="text-2xl font-semibold text-neutral-900 dark:text-neutral-100"><code class="text-purple-600 dark:text-purple-300">scroll-padding</code> vs <code class="text-purple-600 dark:text-purple-300">scroll-margin</code></h2>
    <p class="text-neutral-600 dark:text-neutral-400 leading-relaxed">
      <code class="text-purple-600 dark:text-purple-300 bg-purple-50 dark:bg-purple-900/50 px-1.5 py-0.5 rounded">scroll-margin</code> (on the <strong>target</strong> element) grows how big the element is considered for scroll alignment—useful when one section needs a different offset than others.{" "}
      <code class="text-purple-600 dark:text-purple-300 bg-purple-50 dark:bg-purple-900/50 px-1.5 py-0.5 rounded">scroll-padding</code> on the scrollport applies the same inset for <strong>every</strong> scroll into that viewport, which matches global UI like a fixed nav height.
    </p>
    <p class="text-neutral-600 dark:text-neutral-400 leading-relaxed">
