  <section class="space-y-6 max-w-3xl mx-auto">
    <h2 class="text-2xl font-semibold text-neutral-900 dark:text-neutral-100">What does <code>interpolate-size</code> do?</h2>
    <p class="text-neutral-600 dark:text-neutral-400 leading-relaxed">
      By default, CSS cannot animate between a concrete length and an intrinsic size keyword. The browser simply doesn't know how to interpolate <code class="text-purple-600 dark:text-purple-300 bg-purple-50 dark:bg-purple-900/50 px-1.5 py-0.5 rounded">height: 0</code> → <code class="text-purple-600 dark:text-purple-300 bg-purple-50 dark:bg-purple-900/50 px-1.5 py-0.5 rounded">height: auto</code>, so it jumps. The <code class="text-purple-600 dark:text-purple-300 bg-purple-50 dark:bg-purple-900/50 px-1.5 py-0.5 rounded">interpolate-size</code> property changes this by letting you <strong>opt in</strong> to keyword interpolation.
    </p>
    <p class="text-neutral-600 dark:text-purple-300 dark:text-neutral-400 leading-relaxed">
      Setting it to <code class="text-purple-600 dark:text-purple-300 bg-purple-50 dark:bg-purple-900/50 px-1.5 py-0.5 rounded">allow-keywords</code> tells the browser to resolve the intrinsic size at animation time and interpolate from there. The default value is <code class="text-purple-600 dark:text-purple-300 bg-purple-50 dark:bg-purple-900/50 px-1.5 py-0.5 rounded">numeric-only</code>, which preserves the pre-existing (non-animating) behaviour.
    </p>
    <p class="text-neutral-600 dark:text-neutral-400 leading-relaxed">
      Because the property is <strong>inherited</strong>, you can enable it for an entire document in one line — or scope it tightly to a single component:
    </p>

    <div class="rounded-lg bg-gray-950 border border-gray-800 p-4 font-mono text-xs leading-6">
      <div class="text-gray-500 mb-1">/* document-wide opt-in */</div>
      <div class="text-gray-300">
        <span class="text-sky-400">:root</span>{" {"}
      </div>
      <div class="pl-4 text-gray-300">
        <span class="text-sky-400">interpolate-size</span>{": "}
        <span class="text-emerald-400">allow-keywords</span>{";"}
      </div>
      <div class="text-gray-300">{"}"}</div>
      <div class="text-gray-500 mt-3 mb-1">/* scoped to one container */</div>
      <div class="text-gray-300">
        <span class="text-sky-400">.accordion</span>{" {"}
      </div>
      <div class="pl-4 text-gray-300">
        <span class="text-sky-400">interpolate-size</span>{": "}
        <span class="text-emerald-400">allow-keywords</span>{";"}
      </div>
      <div class="text-gray-300">{"}"}</div>
    </div>
  </section>

  <section class="space-y-6 max-w-3xl mx-auto">
    <h2 class="text-2xl font-semibold text-neutral-900 dark:text-neutral-100">Why <code>height: auto</code> used to snap</h2>
    <p class="text-neutral-600 dark:text-neutral-400 leading-relaxed">
      CSS transitions and animations require both endpoints to be <strong>interpolatable</strong> — meaning the browser must be able to compute a value at any point between them. Concrete lengths like <code class="text-purple-600 dark:text-purple-300 bg-purple-50 dark:bg-purple-900/50 px-1.5 py-0.5 rounded">0px</code> and <code class="text-purple-600 dark:text-purple-300 bg-purple-50 dark:bg-purple-900/50 px-1.5 py-0.5 rounded">200px</code> are easy: linear math. Intrinsic keywords like <code class="text-purple-600 dark:text-purple-300 bg-purple-50 dark:bg-purple-900/50 px-1.5 py-0.5 rounded">auto</code> are not a number — they depend on content, which makes interpolation undefined.
    </p>
    <p class="text-neutral-600 dark:text-neutral-400 leading-relaxed">
      Rather than silently enable this globally — which would break existing pages that rely on the snap behaviour — the CSS Working Group decided to gate it behind an explicit opt-in. The demos below show the difference: the left panel uses <code class="text-purple-600 dark:text-purple-300 bg-purple-50 dark:bg-purple-900/50 px-1.5 py-0.5 rounded">numeric-only</code> (snaps), the right uses <code class="text-purple-600 dark:text-purple-300 bg-purple-50 dark:bg-purple-900/50 px-1.5 py-0.5 rounded">allow-keywords</code> (animates). For filling the inline size of a box without the classic <code class="text-purple-600 dark:text-purple-300 bg-purple-50 dark:bg-purple-900/50 px-1.5 py-0.5 rounded">100%</code> + margin foot-gun, see <a href="/l/width-stretch" class="inline whitespace-nowrap text-purple-600 dark:text-purple-300 underline font-mono text-sm px-1.5 py-0.5 rounded bg-purple-50 dark:bg-purple-900/50">width: stretch</a>.
    </p>
  </section>

  <section class="space-y-6 max-w-3xl mx-auto">
    <h2 class="text-2xl font-semibold text-neutral-900 dark:text-neutral-100">What can be interpolated</h2>
    <p class="text-neutral-600 dark:text-neutral-400 leading-relaxed">
      With <code class="text-purple-600 dark:text-purple-300 bg-purple-50 dark:bg-purple-900/50 px-1.5 py-0.5 rounded">allow-keywords</code> active, you can animate between a <strong>length or percentage</strong> and any of these intrinsic keywords:
    </p>
    <ul class="space-y-1 text-neutral-600 dark:text-neutral-400 leading-relaxed list-disc list-inside">
      <li><code class="text-purple-600 dark:text-purple-300 bg-purple-50 dark:bg-purple-900/50 px-1 py-0.5 rounded text-sm">auto</code></li>
      <li><code class="text-purple-600 dark:text-purple-300 bg-purple-50 dark:bg-purple-900/50 px-1 py-0.5 rounded text-sm">min-content</code></li>
      <li><code class="text-purple-600 dark:text-purple-300 bg-purple-50 dark:bg-purple-900/50 px-1 py-0.5 rounded text-sm">max-content</code></li>
      <li><code class="text-purple-600 dark:text-purple-300 bg-purple-50 dark:bg-purple-900/50 px-1 py-0.5 rounded text-sm">fit-content</code></li>
      <li><code class="text-purple-600 dark:text-purple-300 bg-purple-50 dark:bg-purple-900/50 px-1 py-0.5 rounded text-sm">content</code> <span class="text-xs">(for flex-basis)</span></li>
    </ul>
    <p class="text-neutral-600 dark:text-neutral-400 leading-relaxed">
      One side of the transition must always be a concrete length or percentage — animating between <em>two</em> intrinsic keywords is not supported. If you also need arithmetic on the intrinsic size (e.g. <code class="text-purple-600 dark:text-purple-300 bg-purple-50 dark:bg-purple-900/50 px-1.5 py-0.5 rounded">auto + 2rem</code>), use the <a href="https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/calc-size" class="text-purple-600 dark:text-purple-300 underline" target="_blank" rel="noopener">calc-size()</a> function instead.
    </p>
  </section>

  <section class="space-y-3 max-w-3xl mx-auto">
    <h2 class="text-2xl font-semibold text-neutral-900 dark:text-neutral-100">Browser availability</h2>
    <p class="text-neutral-600 dark:text-neutral-400 text-sm leading-relaxed">
      <strong>Experimental — not yet Baseline.</strong> Supported in Chromium browsers (Chrome/Edge 129+, Opera 115+, Samsung Internet 28+); <strong>not supported</strong> in Firefox or Safari. Check <a href="https://caniuse.com/?search=interpolate-size" class="text-purple-600 dark:text-purple-300 underline" target="_blank" rel="noopener">Can I Use</a> or <a href="https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/interpolate-size#browser_compatibility" class="text-purple-600 dark:text-purple-300 underline" target="_blank" rel="noopener">MDN</a> for the latest figures.
    </p>
    <p class="text-neutral-600 dark:text-neutral-400 text-sm leading-relaxed">
    The fallback is graceful — content still toggles, just without animation; use <code class="text-purple-600 dark:text-purple-300 bg-purple-50 dark:bg-purple-900/50 px-1 py-0.5 rounded">@supports (interpolate-size: allow-keywords)</code> to apply the transition only where it works.
    </p>
